更新基于 Hugo 和 GitHub Pages 的博客，流程其实很固定：**在本地写好 Markdown 文件，`git push` 推送到 GitHub，剩下的构建和部署交给 GitHub Actions 自动完成**。你不需要手动运行 `hugo` 命令来生成网站，也不需要手动上传 `public` 文件夹。

### ✍️ 第一步：创建一篇新文章

首先，在你的博客项目根目录下，用 Hugo 命令生成文章骨架。这比手动新建文件更规范，会自动填好标题、日期等基础信息。

```bash
hugo new content/posts/你的文章文件名.md
```
这条命令会在 `content/posts/` 目录下创建一个新的 Markdown 文件。

打开这个文件，你会看到开头有一段用 `---` 包裹的配置区域，这叫做 **Front Matter**，非常重要。

```markdown
---
title: "我的新文章"
date: 2026-11-23
draft: true
---
```
**需要特别注意两个字段：**
1.  **`draft`**：Hugo 默认会忽略 `draft: true` 的文章。**要让文章上线，必须将其改为 `draft: false`**。这是文章“不出现”最常见的原因。
2.  **`date`**：如果日期被设置成未来的时间，Hugo 默认也不会发布它。

### 👀 第二步：本地预览（推荐）

在推送之前，最好先在本地看看效果，避免带着错误上线。

```bash
hugo server -D
```
这条命令会启动一个本地服务器（通常是 `http://localhost:1313`）。`-D` 参数表示“**包含草稿**”，这样即使文章还是 `draft: true`，你也能在本地预览到。你一边编辑 Markdown，浏览器页面会自动刷新。

确认无误后，按 `Ctrl + C` 停止本地服务器。

### 🚀 第三步：提交代码

这是让线上更新的关键。在你的项目根目录下，执行标准的 Git 操作：

```bash
git add .
git commit -m "添加新文章：我的新文章"
```

### 🚀 第四步：推送到线上

```bash
git push
```
推送完就不用管了，GitHub Actions 会在后台自动帮你打包发布，一两分钟后刷新网页就能看到。

当你把改动推送到 GitHub 的主分支（通常是 `main` 或 `master`）后，**GitHub Actions 会被自动触发**。它会按照预设的工作流（通常在 `.github/workflows/` 目录下的某个 yml 文件中），自动安装 Hugo、构建站点，并把生成好的静态文件部署到 GitHub Pages 上。

**你不需要做任何额外操作**。推送后，稍等一两分钟，访问你的博客地址 `https://*.github.io/` 就能看到更新了。

### 🔍 如何确认部署状态？

如果你想确认自动化部署是否成功，可以去你的 GitHub 仓库页面，点击顶部的 **“Actions”** 标签页。你会看到最近的工作流运行记录，绿色对勾✅表示部署成功，红色叉号❌则表示构建失败，点进去可以查看具体的错误日志。

### 💎 小结：一句话流程

**`hugo new` 创建文章 → 写 Markdown、设 `draft: false` → `hugo server -D` 本地预览 → `git push` 触发自动部署 → 去 Actions 页看结果。**

### 搜索功能（可选）：
配置文件里保留了搜索的设置，但要在网页右上角真正出现搜索框，还需要在 content/ 目录下建一个 search.md 文件，并在里面写上：

```
title: "搜索"  
layout: "search"  
summary: "search"  
placeholder: "输入关键词..."  
```
