# 校园网络规划与建设方案

## 一、项目背景与建设目标

随着学校信息化建设的不断深入，校园网同时承载着教学、办公、安防监控、门禁广播以及服务器等多种业务。不同业务对安全性、实时性和带宽的需求差异很大，如果全部混在一个二层网络里，容易出现广播风暴、互相干扰、安全边界模糊等问题。因此，需要对校园网进行统一的 VLAN（虚拟局域网）划分，并配套完整的安全、可靠与运维设计。

本方案结合学校具体情况，给出一套覆盖网络设备管理、电子教室、安防物联网、无线准入、教师办公、学生上网以及服务器区的整体规划。

建设目标：

1. **业务隔离**：教学、办公、学生、安防、服务器等不同业务分属独立的二层域，控制广播范围；
2. **安全可控**：通过访问控制列表（ACL）控制 VLAN 间互访，对管理区、监控区、服务器区实行最小权限开放；
3. **统一管理**：路由器、交换机、无线 AP 纳入独立管理 VLAN，便于集中运维；
4. **高可靠**：关键设备与链路冗余，避免单点故障导致全校断网；
5. **便于扩展**：编号与地址留有间隔，后续可按业务需要灵活新增；
6. **合规可审计**：满足网络安全等级保护相关要求，日志留存与访问行为可追溯。

## 二、VLAN 总体规划

| 项目 | 描述 |
| --- | --- |
| VLAN1 | 管理 VLAN，路由器、交换机及 AP 使用 |
| VLAN3 | 电子教室 |
| VLAN4 | 监控、广播、门禁 |
| VLAN6 | 免认证 VLAN，白板 |
| VLAN8 | 教师 VLAN |
| VLAN10 | 学生 VLAN |
| VLAN100 | 服务器、打印机 |

## 三、各 VLAN 设计说明

### 1. VLAN1 —— 网络设备管理 VLAN

用于路由器、交换机、无线 AP 等网络设备本身的管理地址，是整网的"运维通道"。所有设备网管地址、AP 管理地址统一纳入该 VLAN，由 DHCP 服务器集中分配。

设计要点：

- 仅允许运维管理终端访问该 VLAN，禁止普通用户 VLAN 访问，防止网络设备被未授权登录；
- 建议对交换机管理口启用 SSH、ACL 登录限制，修改默认口令；
- AP 的管理地址与业务 SSID 分离，用户无法直接触达 AP 管理界面。

> 说明：本规划按学校的既有习惯使用 VLAN1 作为管理 VLAN。从安全最佳实践看，管理 VLAN 应避免承载用户流量，并做好严格的访问限制。

### 2. VLAN3 —— 电子教室

面向电子教室的教学终端，终端数量多、并发高，且常涉及批量分发、屏幕广播等教学活动。

设计要点：

- 允许访问教学服务器及互联网；
- 按需开启端口隔离，限制学生机之间的互访，降低病毒横向传播风险；
- 对视频类广播流量做广播抑制与 QoS 保障，避免影响其他业务。

### 3. VLAN4 —— 监控、广播、门禁

属于弱电/物联网类业务，包括视频监控摄像头、IP 广播终端、门禁控制器等。这类终端位置固定、数量庞大，且摄像头会产生持续的大流量视频流。

设计要点：

- 单独隔离，避免视频流冲击教学与办公网络；
- 仅允许访问 NVR/存储服务器、门禁管理平台（专用管理服务器）以及运维终端；
- 默认禁止访问互联网及其他业务 VLAN，防止安防设备被入侵后横向移动；
- 建议开启 DHCP Snooping防止私接设备。

### 4. VLAN6 —— 免认证 VLAN（白板）

用于无法运行 802.1X 客户端或 Portal 认证的设备，例如交互式白板、考勤机、投影等。这类设备通常不支持标准准入流程，因此单独划分免认证 VLAN。

设计要点：

- 接入时不触发网络准入认证，但应配合 MAC 地址白名单或端口绑定，防止随意接入；
- 仅放通白板应用所需的服务器地址和互联网访问，不做全通策略；
- 可在该 VLAN 内单独设置带宽与会话限制。

### 5. VLAN8 —— 教师 VLAN

面向教职工办公与教学终端，如教师笔记本、台式机、移动设备。

设计要点：

- 允许访问服务器区（VLAN100）、互联网；
- 建议启用 802.1X 或 Portal 认证，按身份下发访问控制策略；
- 与教师业务系统、教务系统、共享打印等资源保持畅通。

### 6. VLAN10 —— 学生 VLAN

面向学生终端，包括学生自带笔记本、手机等无线/有线接入设备，是终端数量最多、安全风险最高的区域。

设计要点：

- 启用 Portal 或 802.1X 认证，实现实名接入；
- 默认与教师 VLAN、管理 VLAN、监控 VLAN、服务器 VLAN 隔离，仅允许访问互联网及指定的教学服务；
- 可结合上网行为管理与带宽限制，保障教学时段关键业务的带宽；
- 禁止访问网络设备管理地址，防止对网关、AP 进行扫描和攻击。

### 7. VLAN100 —— 服务器与打印机

核心业务区，集中部署各类服务器、网络打印机、存储平台等。

设计要点：

- 服务器网关建议设在核心交换机或防火墙上，便于统一做安全策略；
- 对外提供服务的服务器应部署在 DMZ 区域，不直接暴露在内网 VLAN 中；
- 打印机仅允许授权 VLAN（教师、电子教室等）访问，避免滥用；
- 该 VLAN 是各业务 VLAN 的集中访问对象，应作为安全防护重点，开启日志审计与入侵防护；
- 条件允许时，服务器与打印机进一步用防火墙或私有 VLAN 隔离，避免打印机成为横向移动的跳板。

## 四、IP 地址与网关规划建议

在 VLAN 划分确定后，需要为每个 VLAN 规划独立的 IP 网段。以下为建议示例，实际地址应结合学校现有地址规范调整。

| VLAN | 业务 | 建议网段 | 建议网关 |
| --- | --- | --- | --- |
| VLAN1 | 网络设备管理 | 10.0.1.0/24 | 10.0.1.1 |
| VLAN3 | 电子教室 | 10.0.3.0/24 | 10.0.3.1 |
| VLAN4 | 监控、广播、门禁 | 10.0.4.0/24 | 10.0.4.1 |
| VLAN6 | 免认证（白板） | 10.0.6.0/24 | 10.0.6.1 |
| VLAN8 | 教师 | 10.0.8.0/24 | 10.0.8.1 |
| VLAN10 | 学生 | 10.0.10.0/24 | 10.0.10.1 |
| VLAN100 | 服务器、打印机 | 10.0.100.0/24 | 10.0.100.1 |

规划要点：

- 各 VLAN 网关统一采用 `X.X.X.1`，便于识别与记忆；
- DHCP 服务器可集中部署在服务器区，其他 VLAN 通过 DHCP Relay（中继）获取地址；
- 网络设备管理地址建议手工规划并登记台账，与动态分配地址分开；
- **地址连续性**：按楼栋、业务、校区连续分配网段，每段预留 20%~30% 空间，避免后期地址不足再次割接；
- **路由汇总**：在核心与出口设备上对连续网段做路由聚合，减小路由表规模、提升收敛速度；
- **网关位置权衡**：集中网关便于统一管理，分布式网关（下沉到汇聚）可减轻核心压力、缩小故障域，可按校区规模选择；
- **IPv6 提前规划**：教育网常有 IPv6 接入需求，建议按双栈设计，IPv6 前缀、DHCPv6、ND 与安全策略同步规划，避免后期改造。

## 五、VLAN 间路由与访问控制

三层网关建议集中在核心交换机（或路由器）上，以 SVI（交换虚拟接口）方式实现。默认各 VLAN 之间隔离，按需逐条放通。

| 源 VLAN | 目的 | 建议策略 |
| --- | --- | --- |
| VLAN1（管理） | 全网设备 | 仅运维终端可访问；禁止其他 VLAN 主动访问 VLAN1 |
| VLAN3（电子教室） | VLAN100、互联网 | 允许访问教学服务器与打印机；按需限制学生机互访 |
| VLAN4（监控/门禁） | VLAN100 平台 | 仅访问 NVR、门禁管理平台；禁止访问互联网及其他 VLAN |
| VLAN6（白板） | VLAN100、互联网 | 仅放通白板应用相关地址与端口 |
| VLAN8（教师） | VLAN100、互联网、跨校区 | 允许访问服务器区及经 SD-WAN 访问另一校区内网 |
| VLAN10（学生） | 互联网、指定教学服务 | 禁止访问 VLAN1、VLAN4、VLAN8、VLAN100（指定服务除外） |
| VLAN100（服务器） | 各业务 VLAN | 按需主动推送/管理；对外服务走 DMZ 发布 |

通过"默认拒绝、按需放通"的策略，可以有效收敛攻击面，避免一个区域感染后波及全网。

## 六、网络架构与高可靠性设计

在 VLAN 规划基础上，整体架构建议采用"核心—汇聚—接入"分层模型，并针对关键节点做冗余：

- **核心层双机**：核心交换机采用堆叠、IRF 或虚拟化技术，或双机配合 VRRP，避免核心单点故障；
- **汇聚双上联**：汇聚交换机分别上联到两台核心，链路使用 LACP 聚合，兼顾带宽与冗余；
- **出口冗余**：两校区出口 SD-WAN 设备、防火墙建议双机或双链路部署，配合链路质量探测实现主备切换或负载分担；
- **接入层防护**：开启 STP 根保护与 BPDU 保护，防止私接交换机造成环路；
- **服务器区冗余**：关键服务器网卡绑定、存储冗余、UPS 供电，保障业务连续性。

## 七、无线接入与准入认证

- 无线 AP 的管理地址划入 **VLAN1**，保证运维通道独立；
- 教师 SSID 对应 **VLAN8**，学生 SSID 对应 **VLAN10**，通过 802.1X / Portal 认证后动态下发；
- 白板、教学一体机等无法认证的设备接入 **VLAN6**，配合 MAC 白名单使用；
- 如需访客网络，可新增独立 VLAN（例如 VLAN20），仅放行互联网访问，且与校内资源完全隔离；
- **先勘测再布点**：不要仅凭经验放置 AP，图书馆、会议室、体育馆、宿舍等场景要做容量与信号仿真，高密度区域单独设计；
- **信道与功率规划**：2.4G 使用 1/6/11 错开，5G 合理规划信道并适当降低发射功率，减少同频干扰；
- **POE 供电**：确认 POE 交换机功率预算充足，弱电间供电与散热到位；
- **漫游优化**：启用 802.11k/v/r，通过 AC 集中管理，保障师生移动时业务不中断。

## 八、网络安全体系设计

建议对齐网络安全等级保护 2.0 相关要求，构建分层防护体系：

- **边界防护**：出口部署防火墙、IPS、上网行为管理；服务器区前置防火墙，数据库不对公网开放；
- **准入控制**：教师/学生实名认证，访客单独认证与隔离，物联网设备做 MAC 白名单绑定；
- **最小权限**：各 VLAN 默认隔离，按业务逐条放通，管理 VLAN 严格限定来源；
- **日志审计**：网络设备、安全设备、服务器日志集中收集并留存（等保通常要求不少于 180 天）；
- **主动防御**：定期漏洞扫描、补丁管理与弱口令排查，重点保护教务、一卡通、财务等系统；
- **数据保护**：重要业务数据定期备份，关键系统考虑异地备份。

## 九、QoS 与带宽管理

校园网业务类型多，建议按重要程度分级保障：

1. 教学与教务系统（选课、教务管理、在线教学）；
2. 教师办公与视频会议；
3. 学生上网；
4. P2P 下载、娱乐流量。

实施建议：

- 在核心与出口设备上配置 QoS 队列与优先级标记；
- 监控视频流单独保障带宽，但严格限制其访问范围；
- 学生区设置带宽限制与时段策略，避免晚高峰挤占出口带宽；
- 对 P2P、大流量下载进行识别与限速。

## 十、双校区互联与出口设计

结合学校两个校区出口部署 SD-WAN 设备的现状：

1. **跨校区内网互访**：两个校区的 SD-WAN 设备之间建立加密隧道，实现服务器区（VLAN100）及指定内网服务器的跨校区互访。各校区的 VLAN 在本地独立存在，不建议跨校区拉伸二层，跨校区通信采用三层路由经 SD-WAN 隧道转发；
2. **应用识别与智能选路**：对关键业务（教务、一卡通、视频会议等）优先保障，按链路质量动态选路；
3. **出口流量分流**：内网互访与服务器流量走 SD-WAN 隧道；互联网访问流量按学校的统一安全策略处理；
4. **出口安全与审计**：部署内部 DNS、上网行为管理与日志审计，统一管控出口流量；
5. **访问控制**：在核心交换机或出口防火墙上针对跨校区流量配置 ACL，仅放通必要的服务器端口，避免整段互通；
6. **合规提示**：如涉及访问境外网络资源，应通过合规的国际专线或经授权的服务实现，并符合相关管理规定。

## 十一、运维管理与台账

长期可维护性往往决定网络的实际效果，建议做好以下工作：

- **统一网管平台**：设备状态监控、流量告警、拓扑可视化，故障主动发现；
- **配置备份与变更管理**：定期自动备份设备配置，变更前后留存记录，便于回滚；
- **资产台账**：建立 VLAN、IP、MAC、端口、位置、使用人的对应台账，与本文 VLAN 表配套维护；
- **定期审计**：审查 ACL 与策略有效性，清理无效规则，核对台账与实际是否一致；
- **应急预案**：针对出口故障、核心故障、广播风暴、病毒爆发等场景制定处置流程并演练。

## 十二、实施风险与常见误区

规划与实施中应重点避开以下问题：

1. 管理 VLAN 使用 VLAN1 却不做访问限制，导致全网可扫描到网络设备；
2. VLAN 建了但默认全互通，隔离策略形同虚设；
3. 监控、门禁直接接入业务网，视频流冲击教学网络；
4. 无线 AP 不勘测、信道不规划，出现"能连但不好用"；
5. 缺少 IP/MAC 台账，故障排查效率极低；
6. 出口单设备、单链路，故障即全校断网；
7. 忽略日志留存与合规要求，等保验收时难以补齐；
8. 服务器与打印机混放且无隔离，打印机成为横向移动跳板。

## 十三、分阶段实施建议

1. **第一阶段**：完成核心、汇聚架构与冗余配置，创建 VLAN 与 SVI，配置 Trunk 与 ACL 框架；
2. **第二阶段**：上线管理 VLAN 与服务器区，配置 DHCP、DNS 与日志审计；
3. **第三阶段**：部署电子教室、教师与学生区，完成准入认证策略；
4. **第四阶段**：部署无线 AP，完成信道规划、POE 供电与漫游优化；
5. **第五阶段**：上线免认证白板、监控门禁等物联网 VLAN，完成安全策略验证；
6. **第六阶段**：接入双校区 SD-WAN，配置跨校区互访与出口分流策略；
7. **验收与交付**：逐项验证"该通的通、该断的断"，完成台账、文档与运维交接。

## 十四、总结

本方案通过 7 个 VLAN 对校园网进行逻辑分区，覆盖网络设备管理、电子教室、安防物联网、免认证教学设备、教师办公、学生上网以及服务器区，实现了业务隔离与安全可控。在此基础上，进一步补充了 IP 与 IPv6 规划、高可靠架构、无线覆盖、等级保护、QoS、运维台账以及双校区 SD-WAN 互联等内容，形成一套从规划、建设到运维的完整体系。该方案结构清晰、扩展性强，可作为学校校园网建设与改造的基础参考文档。
